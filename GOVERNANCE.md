# Governance

potato box uses a maintainer-led, contribution-friendly model.

## Roles

- **Contributors** submit issues, documentation, tests, designs, and code.
- **Maintainers** triage, review, merge, release, and manage security reports.
- **Lead maintainer** resolves deadlocks, appoints maintainers, and protects project scope and licensing.

## Decision Process

Routine changes use pull-request review. Significant changes to project format, security boundaries, provider abstractions, or governance require a written design or ADR and a documented maintainer decision.

Decisions prioritize, in order:

1. user data integrity and recoverability;
2. security and privacy;
3. behavioral clarity and backward compatibility;
4. maintainability and testability;
5. performance and convenience.

Maintainers disclose conflicts of interest and do not approve their own security-sensitive change without another reviewer when another maintainer is available.

## Maintainer Changes

Maintainers are selected based on sustained, constructive contributions and sound judgment. A maintainer may step down voluntarily or be removed for inactivity, repeated policy violations, compromised accounts, or conduct that threatens users or the project.

## Project Independence

The project name, roadmap, release process, and current product decisions are governed by potato box maintainers. Historical provenance remains preserved in `LICENSE` and `NOTICE` as required by the license.
